## 為什麼 README／STATE 還寫著 CANDIDATE？

原桌面驗收流程先凍結程式與文件，再跑測試與獨立審查。為了避免最後把文件改成 PASS 卻改變受驗來源，最終結論寫到 `.evidence/desktop/<run-id>/FINAL_RESULT.json`，保留原 README、STATE 與 HANDOFF 的候選快照。因此那些檔案的「待驗收」文字是凍結時的歷史狀態，不是最終結果。

這次只新增 `docs/user/` 的兩份使用者文件，沒有改動原引擎、測試、部署模板或既有文件。新增文件會改變整個工作目錄的 source fingerprint；上述完整 FINAL PASS 僅對應原 accepted source。新指南的命令實測、文件檢查及獨立審查另存於 [本次文件證據目錄](../../.evidence/desktop/user-guide-20260927/)，不把歷史結果覆寫成新的全案驗收。

`.evidence/`、工具與快取原本就被 Git 忽略。若要交接到另一台電腦，除了提交程式與文件，也應另行保存驗收證據；單靠 Git checkout 不會自動帶走這些本機紀錄。缺少證據時不能只憑本報告宣稱已重新驗證。

## 正式導入還缺什麼

需要使用者與維運團隊提供真實五條流程內容、外部 API／機器／Kubernetes 目標、測試與正式憑證參照、權限配置、artifact 保存與備份政策，以及正式發布／回復流程。需依 [外部整合檢核表](../operations/EXTERNAL_INTEGRATION_CHECKLIST.md) 在授權環境驗證。

現有工程版本可作為開發、測試與導入基礎。一般使用者可先完成 [使用者指南](使用者指南.md) 的本機練習；正式部署與企業流程遷移尚不能標示為已完成。
